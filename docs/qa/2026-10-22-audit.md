# Проверка equinox — 22 октября 2026

## Что изменено

Исправлен нестабильный графический тест скрытия формы через menu bar:
`testStatusItemToggleHidesOpenDrawersInBothPanelModes` искал окно через
`NSApp.keyWindow`. В полном исходном прогоне окно оказалось nil, тогда как
отдельный повтор прошёл. Теперь тест находит единственную созданную им
`KeyablePanel` независимо от глобального фокуса и проверяет её видимость,
скрытие, повторное открытие и сохранение состояния формы в обоих режимах.

Добавлен `testDateCalendarEscapeDoesNotReachDrawerCancel`: настоящий SwiftUI
popover с календарём принимает первый Escape; форма получает только второй.
Проверяются закрытие popover, сохранение родительского окна и число вызовов
обоих обработчиков. Тест использует синтетическое событие внутри graphics host.

Изменения этой проверки ограничены `equinoxGraphicsTests/SurfaceLayoutTests.swift`
и этим отчётом. Уже существовавшие изменения панелей, локализации, архитектурного
описания и App Store metadata сохранены. Новых изменений production-кода нет.

## Почему так

Зависимость от глобального key window проверяла состояние рабочего стола,
а не контракт скрытия конкретной панели. Исправление не добавляет повторных
попыток, не убирает assertions и не меняет приложение ради теста.

При управлении живым приложением через Computer Use один Escape закрыл форму
после открытия выбора даты. Это наблюдение **не подтверждено как дефект продукта**:
изолированный тест с настоящим popover проходит на исходном обработчике
`onExitCommand`. Переключение фокуса инструментом могло повлиять на результат.
Пробная замена обработчика отменена. Нужна повторная живая проверка с фокусом
в popover; блокировка Mac помешала её завершить.

Пройдены все существующие наборы, включая даты поддерживаемых лет, DST,
all-day, раскладку многодневных событий, валидацию новых событий, повторы,

живые операции EventKit.

Графическая матрица включает S/M/L, glass/solid, light/dark, состояния доступа,
загрузки/ошибки/пустых данных, длинные названия, формы и все вкладки настроек.

маленькой светлой панели с ошибкой и тёмной вкладки Appearance. Это выборочный
просмотр, не ручная проверка каждого изображения матрицы.

До блокировки Mac в Release проверены открытие формы без календарного доступа,
предупреждение об отсутствии writable-календаря, disabled-сохранение,
начальный фокус названия, установка текста и открытие выбора даты.

## Риски

- Computer Use дважды подтвердил блокировку Mac. Запрос разблокировки отправлен;
  на момент завершения отчёта ответа нет.
- Приложение показывало отсутствие Calendar access. Отправлен отдельный запрос
  разрешения на выдачу полного доступа; разрешение не получено и доступ не выдан.
- В offscreen-рендере тёмного sidebar выбранная строка чёрная, подписи плохо
  различимы. Предыдущий аудит также фиксировал ограничение захвата стандартного
  SwiftUI List. В живом окне текущее поведение не проверено; косметический обход
  без подтверждения дефекта не добавлен.
- macOS 26.0 не проверена. Локальная подпись не подтверждает distribution/archive.
- Логи содержат системные сообщения CoreSimulator/version mismatch,
  linkd.autoShortcut и StatusBar. Отсутствие runtime warnings в xcresult не
  означает отсутствия любых диагностик ОС.

## Что не сделано

Полная живая приёмка остаётся открытой: fetch/create/delete QA-событий, повторы
через настоящий EventKit, внешняя синхронизация, живые фильтры календарей,
горячая клавиша, настройки и их сохранение после изменения/перезапуска,
все сочетания тем и размеров в реальном окне, повторная проверка Escape.
Эти пункты требуют разблокированного Mac; календарные операции также требуют
разрешённого доступа Equinox к календарям.

QA-события не создавались: удалять календарные данные после этой проверки не нужно.
Настройки приложения намеренно не изменялись, TCC не сбрасывался. Новый исходный
код приложения, зависимости, signing, проект, публикация и выпуск версии не менялись.
